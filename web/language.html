Scripts

A script is a tree of <seq> tags. A sequence either plots a formula, or contains other sequences, which are layered back to front in the order written. Every sequence has a start time (debut, in seconds, relative to its parent) and a duration; a container lasts as long as its children need. Children inherit all of their parent's properties.

// a two-second movie, 320x240 at 24 fps, oversampled
<seq fw=320 fh=240 framerate=24 oversample>
  <seq id=a debut=0 duration=1 center width=4 min=-1 mono="fnoise(x,y,t)" />
  <seq debut=last duration=1 hsv=".6, $a, 1-$a" />
</seq>

Values are numbers, bare words or quoted strings; a formula goes in quotes. debut=last means "when the previous sibling ends". Times may be written mm:ss. Comments start with //.

<map> is a sequence that is only ever sampled, never drawn.

Formulas

Ordinary arithmetic with + - * / ^ (or **), %/mod, comparisons < <= = == != <> >= > (giving 1 or 0), &&/and, ||/or, bitwise & | xor ~, and cond ? a : b. Case does not matter. pi, pi2 (2π) and e are constants.

Live shader

The Live shader tab, the editor's usual view, compiles the script to a GLSL fragment shader and plays it on the GPU, looping every duration seconds, at whatever size the size boxes say; edits recompile as you type. The Frame tab renders one frame with the original engine instead (WebAssembly, on every core): exact, frame-stepped, and the one to use where the GPU is weak. The editor remembers which tab you last used. Save frame (PNG) and Render movie… work from either: a movie is drawn by the shader unless the dialog says to use the original renderer (or the shader didn't compile), and the frames show as they are made. Save shader (HTML) writes a page that plays the loop by itself, with the shader and any images inside it (space pauses, arrows step, s saves a frame, o toggles oversampling). Save GLSL writes the fragment shader alone, in Shadertoy's dialect (mainImage, iTime, iResolution, iChannel0…), so it can be pasted there (give its channels the script's images, nearest filtering, no vertical flip).

The shader follows the renderer: layers, bounds, zoom, min/max, wrap, cycle, oversample, the blend modes, sampling of other sequences and images, noise, fractals and the rest. It differs in being 32-bit float where the renderer is double (the deep Mandelbrot zooms in the examples, with widths of a billionth, dissolve into noise on the GPU; shallow ones are fine), in time being continuous rather than stepping by frames, and in ? giving a different random stream. Where the formulas leave their domain (bias, gain and two-argument ease outside 0..1, for instance) the renderer makes NaNs and the GPU makes something else, and a sequence sampled outside its own lifetime is undefined in both. A few things can't be done in a shader: sequences that sample each other in a cycle, more than four images, and iteration counts (recurse) above 4000. Scripts that use fnoise/turb under several sampled layers with oversampling can be heavy; untick oversample for four times the speed.

Notes

  • This is the renderer of QTS (2001–2003), the last version of Pixel Magic, ported from its C++ source; the sample scripts are the originals and render as they did then, quirks included.
  • Renders are deterministic: the same script gives the same pixels here and in the native qts tool.
  • Movies render on the GPU by default; the original renderer uses every core in your machine, but it is still a formula per pixel per frame, so long movies take minutes that way.
